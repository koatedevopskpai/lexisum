# L05: practical offline CI

The explicit offline-core profile runs the parser, real TF-IDF/TextRank extractor,
normalised source auditor, DOCX/PDF format checks and usage-accounting checks on
short authored fixtures. Existing SBERT selection tests inject fixed embeddings;
they do not download Sentence-Transformers weights or validate semantic quality.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-offline.lock
.venv\Scripts\python -m pytest -c pytest-offline.ini --junitxml=artifacts/offline-results.xml
```

The workflow uses exactly that lock and pytest command on CPython 3.12. Package
installation requires a package source; test execution blocks outbound Python
connections and disables dotenv loading. There is no provider key, cloud setup,
torch, Sentence-Transformers or language-model download in this profile. spaCy's
existing blank-English fallback is exercised deliberately. The guard is a
process-local test safeguard, not an operating-system isolation guarantee.

The estimator test supplies a fixed encoder to exercise accounting without
tiktoken's first-use download; actual provider tokenisation is not validated.
Usage-log checks use real numeric counts and the repository's dated pricing
snapshot. DOCX/PDF checks establish container/content generation, not rendered
layout quality. A passing auditor still means only the matching semantics in
AUDITOR_SEMANTICS.md.

The larger existing suite and CUAD benchmark remain separate commands; this
profile does not skip or xfail their tests. Live generation/full benchmark work
is intentionally absent from automatic CI. Run those explicitly with a budget
and dependencies when their separate tasks are authorised. An offline CI pass
is never a reproduced benchmark or a fresh legal-summary quality result.

Generated artifacts are ignored and uploaded by CI. Durable run evidence belongs
in evidence/L05.md, and local receipts in the handoff folder.
